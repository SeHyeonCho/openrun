# 🎟️ OpenRun

> 소규모 공연의 선착순 판매에서 입금 대기부터 환불·입장까지 좌석 정합성을 지키는 예매 엔진.

선착순 예매의 동시성 문제를 락 전략별로 직접 구현하고, 같은 조건의 부하 테스트 수치로 비교해 보려고 시작한 프로젝트다.

## 🎯 가상 고객

구글폼·DM과 계좌 입금으로 티켓을 파는 수백 석 이하 소규모 공연 주최자를 가상 고객으로 둔다. 이 고객과 아래 문제는 공개 자료에서 세운 가설이고, 주최자에게 직접 검증하지 않았다. 실제 돈을 받지 않는 포트폴리오 프로젝트다.

## 🧩 핵심 문제

- 좌석은 한정 자원이라 초과 판매가 발생하면 안 된다
- 입금을 기다리는 동안 좌석을 잡아 두어야 하고, 만료 뒤에 늦은 입금이 들어올 수 있다
- 입금 확인, 환불, 입장 확인의 상태가 끊기지 않고 이어져야 한다
- 결제 같은 느린 외부 I/O가 처리 흐름 중간에 들어온다
- 드문 인기 공연에서는 오픈 시점에 동시 요청이 몰린다
- 서버가 여러 대인 분산 환경

## 🛠 기술 스택

- Java 21, Spring Boot 4
- MySQL 8, Redis (Redisson)
- Gradle, Docker Compose

## 🚀 로컬 실행

```bash
# 1. 환경 변수 파일 준비 (필수)
cp .env.example .env
# 필요하면 .env 안의 값(비밀번호·포트)을 수정

# 2. 인프라(MySQL · Redis) 띄우기
docker compose up -d

# 3. IDE에서 애플리케이션 실행
```
- `.env`는 필수다. 없으면 앱이 시작 단계에서 실패한다.
- 실행 프로필 지정: IDE 실행 구성의 Active profiles에 `local`을 지정해야 한다. (또는 VM 옵션 `-Dspring.profiles.active=local`)
- DB·Redis는 Docker로 띄우고, 애플리케이션은 IDE에서 직접 실행한다.
- 종료: `docker compose down`
- Git 훅 활성화: 클론한 뒤 `git config core.hooksPath .githooks`를 한 번 실행한다. 커밋 메시지 형식과 브랜치 이름을 검사한다.
