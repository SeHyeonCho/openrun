# 0001. 구매자 로그인 방식

- 상태: 채택
- 날짜: 2026-11-14
- 관련: #39, [API 명세](../spec/booking-api.md) 2절

## 맥락

- 선점·확정·내 주문은 요청한 사람이 누구인지 알아야 한다. 지금까지는 요청 본문의 `userId`를 그대로 믿어서, 아무 값이나 넣으면 남의 이름으로 선점하거나 남의 주문을 확정할 수 있었다
- 1인 최대 좌석 수는 구매자 단위로 센다. 구매자 식별값을 쉽게 새로 만들 수 있으면 한도가 의미를 잃는다
- 구매자는 모바일 웹에서 공연 링크로 들어온다. 판매가 열리는 순간 로그인이나 정보 입력이 길면 그사이 좌석이 팔린다
- 주문 화면과 입장 QR은 함께 갈 사람에게 보여 주거나 입구에서 띄운다. 이 화면까지 로그인을 요구하면 휴대폰을 바꿔 들었을 때 표를 못 연다

## 결정

1. 구매자는 카카오 계정으로 로그인하고 따로 가입하지 않는다. 카카오에서는 계정 식별값과 닉네임만 받는다
2. 로그인 상태는 서버 세션 쿠키로 유지한다. 쿠키는 `HttpOnly`, `Secure`, `SameSite=Lax`이고, 세션은 마지막 요청부터 5시간 동안 요청이 없으면 끝난다
3. 상태를 바꾸는 `POST`는 CSRF 토큰을 검사한다. 서버가 `XSRF-TOKEN` 쿠키를 내려주고, 화면은 그 값을 `X-XSRF-TOKEN` 헤더에 담는다
4. 주문은 128비트 무작위 주문 토큰으로 가리킨다. 토큰만 있으면 주문을 볼 수 있지만, 확정은 주문을 만든 구매자가 로그인해야 한다
5. 다른 구매자의 주문을 확정하려 하면 `403`이 아니라 `404`로 답한다. 그 구매자에게는 확정할 수 있는 주문이 없는 것과 같고, `403`은 그 토큰이 남의 주문이라는 것을 따로 알려 준다

## 버린 대안

- **JWT를 `Authorization` 헤더로 보내고 화면 저장소에 두기**: 로그아웃과 토큰 탈취에 대응하려면 결국 서버에 폐기 목록(Redis 등)을 둬야 한다. 상태를 서버에 두는 것은 세션과 같은데 관리할 곳만 둘이 된다. 화면 저장소의 토큰은 XSS가 생기면 바로 읽힌다
- **JWT를 `HttpOnly` 쿠키에 두고 재발급 토큰을 돌려 쓰기**: 쿠키로 보내므로 CSRF 대응은 세션과 같이 필요하다. 그 위에 재발급, 회전, 폐기를 따로 구현해야 해서 서버 한 대인 지금 얻는 것이 없다
- **비회원 예매(이름·전화번호 + 주문 토큰)**: 기능 명세(#30)를 쓰며 검토했다. 링크를 잃어버렸을 때 찾을 방법, 전화번호를 바꿔 넣는 한도 우회, 판매 오픈 순간의 정보 입력, 실명 확인을 따로 메워야 했다
- **세션을 처음부터 Redis에 두기**: 서버가 한 대인 동안은 메모리 세션과 동작이 같다. 서버를 여러 대로 늘리는 단계(P6)에서 `spring-session-data-redis`로 옮긴다. API와 쿠키는 바뀌지 않는다
- **세션 14일**: 처음에 검토했다. 주문 화면과 QR은 주문 토큰으로 열리므로 오래 로그인해 둘 이유가 선점·확정·내 주문뿐이다. 카카오 로그인이 브라우저에 남아 있으면 다시 로그인은 카카오 화면을 한 번 거치는 것으로 끝난다. 세션이 길면 쿠키를 탈취당했을 때 쓸 수 있는 기간과 서버 메모리에 쌓이는 세션도 늘어난다. 5시간은 판매 오픈을 기다리는 시간과 10분 선점 기한을 덮는다고 보고 정한 값이고, 실제 대기 시간은 측정하지 않은 가설이다
- **`SameSite=Lax`만으로 CSRF를 막기**: 같은 사이트의 다른 하위 도메인에서 오는 요청은 `SameSite`로 막지 못한다. 토큰 검사를 함께 둔다

## 결과

- 세션이 서버 메모리에 있어서 서버를 다시 시작하면 모든 구매자가 다시 로그인해야 한다
- 화면은 로그인할 때 `/oauth2/authorization/kakao`로 이동하고, 로그인이 끝나면 `/`로 돌아온다. 이동하기 전에 저장해 둔 경로로 돌아가는 것은 화면이 맡는다
- 부하 테스트(전략 비교 + 부하 테스트 단계)는 카카오 로그인을 거칠 수 없다. 측정용 인증 경로는 그 단계에서 운영 프로필에서는 켜지지 않게 정한다
- 테스트는 카카오 서버 없이, 로그인한 구매자를 흉내 내거나 카카오 사용자 정보에서 구매자를 찾는 부분을 직접 불러 확인한다
